# clixx-polly

A serverless text-to-speech app on AWS: submit a block of text, and it's converted to an MP3 using Amazon Polly, stored in S3, and made available through a static website. Infrastructure is fully defined in Terraform.

## Architecture

```
Website (S3 static site)
   │  POST /  { text, voice }
   ▼
API Gateway (PostReaderAPI, stage DEV)
   │
   ├── POST ─▶ Lambda PostReader_NewPosts
   │              │  writes item (status: PROCESSING) to DynamoDB `posts`
   │              └─ publishes post ID to SNS topic `new_posts`
   │                       │
   │                       ▼
   │              Lambda PostReader_ConvertToAudio (SNS-triggered)
   │                  │  reads text/voice from DynamoDB
   │                  │  synthesizes speech via Amazon Polly
   │                  │  uploads MP3 to S3 (mp3 bucket, public-read)
   │                  └─ updates DynamoDB item (status: UPDATED, url)
   │
   └── GET ──▶ Lambda PostReader_GetPosts
                  reads/scans DynamoDB `posts` table
```

## Resources

| Resource | Name | Purpose |
|---|---|---|
| S3 bucket | `stack-enoch-polly-website` | Hosts the static website (`website/`) |
| S3 bucket | `stack-enoch-polly-mp3` | Stores generated MP3 files, public-read |
| DynamoDB table | `posts` | Stores post text, voice, status, and resulting audio URL |
| SNS topic | `new_posts` | Fans out new post IDs to the audio-conversion Lambda |
| Lambda | `PostReader_NewPosts` | Creates a post record and publishes to SNS |
| Lambda | `PostReader_ConvertToAudio` | Converts post text to speech via Polly and uploads to S3 |
| Lambda | `PostReader_GetPosts` | Reads a single post or all posts from DynamoDB |
| API Gateway | `PostReaderAPI` (stage `DEV`) | REST API fronting the two entry-point Lambdas, CORS enabled |
| IAM role/policy | `LambdaRoleForPolly` / `LambdaPolicyForPolly` | Shared execution role for all three Lambdas |

## Project layout

```
lambda/
  post_reader_new_posts/index.py        # POST handler: create post, publish to SNS
  post_reader_convert_to_audio/index.py # SNS handler: text -> Polly -> S3
  post_reader_get_posts/index.py        # GET handler: read/scan DynamoDB
website/
  index.html, styles.css, scripts.js    # Static frontend, deployed to the website bucket
*.tf                                    # Terraform: apigateway, lambda, dynamodb, sns, iam, storage, provider, vars, outputs
build/                                  # Zipped Lambda packages (generated by Terraform, gitignored)
```

## Prerequisites

- Terraform >= 1.5.0
- AWS CLI credentials configured under the `stackprog-dev` profile (see [provider.tf](provider.tf) and [versions.tf](versions.tf))
- An existing S3 bucket for Terraform remote state: `enoch-tf-state-bucket` (see the `backend "s3"` block in [versions.tf](versions.tf))

## Deploying

```powershell
terraform init
terraform plan
terraform apply
```

## Outputs

After `apply`, Terraform prints:

- `api_invoke_url` — the API Gateway invoke URL, used as `API_ENDPOINT` in [website/scripts.js](website/scripts.js)
- `website_bucket_endpoint` — the static website's S3 endpoint
- `mp3_bucket_name` — the bucket holding generated MP3s
- `dynamodb_table_name` — the DynamoDB table name

## API

- `POST /` — body `{ "text": "...", "voice": "Mike" }`, returns the new post ID
- `GET /?postId=<id>` — returns the post; use `postId=*` to scan all posts

See [plan.md](plan.md) for the original design notes this Terraform config was built from.
